## 1. 已有证据与待验证问题

主对比表中的实验指标保留在本地，不随代码上传。

模块贡献与统计显著性需通过受控消融检验。预先规定以下问题：

- H1：Token 感知通道显著性有独立贡献。
- H2：Token 加权重建损失有独立贡献。
- H3：两者组合的效果及相互作用能在两种精度下复现。
- H4：重要性与 Token 的对应关系有用，而非任意重加权都能带来改善。
- H5：积分估计相较单点梯度的收益是否值得额外校准成本。

MMStar、TextVQA 的改善和 CV-Bench 等任务上的不足均保留，不只报告有利任务。
不得预填消融分数，也不预设 D 必须优于所有变体。

## 4. 核心模块消融：两个精度各四组

S 表示 token_aware_saliency；L 表示 token_weighted_loss。

| 组别 | S | L | 通道显著性 | 重建目标 |
|---|---:|---:|---|---|
| A Base | 0 | 0 | 统一参考激活统计 | 同一有效 Token 集合上的均匀 MSE |
| B +S | 1 | 0 | Token 感知混合统计，λ=0.5 | 同一有效 Token 集合上的均匀 MSE |
| C +L | 0 | 1 | 统一参考激活统计 | Token 重要性加权 MSE |
| D Full | 1 | 1 | Token 感知混合统计，λ=0.5 | Token 重要性加权 MSE |

所有组固定有效 Token 范围、padding 处理、病例归一化方式、搜索网格和量化算子。
比较 B-A、C-A、D-B、D-C；另外报告交互项 D-B-C+A，不强求交互项为正。

注意：当前代码 L=0 使用视觉 Token mask，L=1 的权重支持视觉和回答 Token。
正式消融需要统一这一支持集合，否则 C-A/D-B 不能单独解释为权重分配的效果。
显著性统计同样需要控制有效 Token 和样本归一化；所有改动要对四组一致。
A 是统一实验框架内的 Base，不直接拿主表 AWQ 的分数代替 A。

若这些控制或数值修正改变完整方法 D，必须重跑 D，并更新对应主对比表中的完整方法结果。
用户提供的 D 行只有在模型、数据、预处理、代码、量化设置、λ 等完全相同时才能复用。

## 5. 重要性机制对照：W3A16

保持 D 的其他设置不变，除默认 IG 外增加两组：

| 组别 | 重要性来源 | 解释 |
|---|---|---|
| D | 32 步积分梯度 | 完整方法 |
| G Grad×Input | 输入点 α=1 的单点梯度乘输入 | 检验积分是否优于便宜的梯度近似 |
| P Permuted-IG | 打乱 IG 权重与 Token 的对应关系 | 检验真正的重要性排序是否有用 |

P 在每个样本、每个模态的有效 Token 内分别打乱，保持模态权重总量及权重分布。
S、L 使用同一份打乱后的权重；不把 padding 纳入打乱。
G 的采样点明确为 α=1，不能把 torch.linspace(0,1,steps=1) 得到的 α=0 当作它。
统一有效集合和归一化后，均匀重要性应退化到 A；先用小规模数值检查验证，再复用 A。
这两组在八项基准上全量评测，不能只挑改善最大的基准。

## 6. 参数敏感性与成本：优先 W3A16

| 因素 | 设置 | 新增搜索数量（可复用项经验证后） |
|---|---|---:|
| λ | 0、0.25、0.5、0.75、1 | 3：0 复用 C，0.5 复用 D |
| 校准量 N | 32、64、128、256 | 3：128 复用 D |
| IG 步数 M | 4、8、16、32 | 3：32 复用 D |
| IQR | on / off | 1：on 复用 D |

固定其他因素逐项改变。λ 不是关闭完整方法的开关：λ=0 时 L 仍然有效，应退化到 C。
N 使用同一预先打乱清单的嵌套子集，并在完整校准候选池足够时取样，不能循环复制到目标数量。
λ、M、N 的推荐值由独立开发集或预先固定的验证准则决定，不根据八项正式评测反复挑选。

预算有限时，这四类敏感性实验预先固定在 MMStar、CV-Bench、TextVQA、VizWiz 四个诊断任务上。
它们覆盖推理、视觉关系、文本识别和真实图像问答；CV-Bench 也用于观察主表中的相对弱项。
若展示四任务平均，明确记为 Avg4-diagnostic，不能与主表 Avg8 比较。
预算充足时，这些配置补齐全部八任务。

## 7. 重复、显著性与原始数据

核心 A/B/C/D 在两个精度下，建议使用三组独立抽取的 128 条校准子集：seed 42、123、2026。
每个 seed 的四组使用相同校准条目与处理后输入；同一个 scale 的重复推理不当作独立校准实验。
当前校准 loader 的 shuffle seed 写死为 42，实施多种子时需显式保存不同条目清单/缓存，不能只改 --seed。

- 每个 benchmark、每个配置保存逐题 ID、原始回答、解析结果和官方逐题计分信息。
- 报告每个任务及 Avg8 在三个校准子集上的均值和标准差，保留未舍入值用于统计。
- 每个任务内部使用相同的逐题重采样索引，成对 bootstrap 10,000 次。
- 对每次重采样重新调用该任务的固定聚合公式，再计算 Avg8 差值与 95% CI。
- 对指定校准 seed 的区间是条件于该校准集的评测样本不确定性；另报告校准子集之间的波动。
- 不对仅有八个总体分数直接做逐题显著性检验；不把不同任务分数当成同分布样本。
- 若同时检验多个模块差值，预先指定主要比较，必要时使用 Holm 校正。

正式展示 D-A、D-B、D-C 的差值及区间。若区间跨 0，不写成显著提升。

## 9. 执行前的实现检查

- 固定 S/L/λ 的实际生效路径；不能把未进入目标函数的 reweight_ratio 当成一个有效模块。
- 明确 W4A8 梯度语义：现有 WALinear.forward 有 no_grad；确认使用 stop-gradient 代理还是可微近似。
  这是方法定义问题，应先固定并验证，再生成正式结果；不能悄悄改变梯度定义后复用旧主表。
- IG 步数、IQR 开关、重要性来源和校准抽样清单需要补充独立配置接口。
- padding 在显著性、重要性归一化、IQR 和损失中的处理需一致，并通过退化检查。
- 缓存指纹包含模型 revision、代码版本、校准 ID、精度、粒度、S/L/λ、M、IQR、权重来源和 seed。
- 每组使用独立 scale/state 路径；搜索后从原始模型应用一次 scale，避免重复缩放。
- 固定任务清单、metric/filter、split、样本数；任务失败或缺失时不生成有效 Avg8。

## 10. 预算与顺序

| 阶段 | 内容 | 独立量化配置数 | 正式评测任务次数 |
|---|---|---:|---:|
| 必做 P0 | 两个精度的四组模块消融，seed42 | 8 | 64 |
| 优先 P1 | 单点梯度与打乱权重机制对照 | 2 | 16 |
| 优先 P1 | λ 曲线的三个新增点 | 3 | 12（诊断四任务） |
| 补充 P2 | 校准量三个新增点 | 3 | 12（诊断四任务） |
| 补充 P2 | IG 步数三个新增点 | 3 | 12（诊断四任务） |
| 补充 P2 | 关闭 IQR | 1 | 4（诊断四任务） |
| 合计 | 主设计，seed42 | 20 | 120 |
| 稳健性扩展 | 核心八组再补两个校准 seed | +16 | +128 |

另有 FP16 八任务参考，可复用配置匹配的已有结果。
20 个配置均补齐八任务时为 160 次任务评测；三种子核心扩展另计。
已有 D 或其他结果是否减少新运行数量，以元数据一致性检查为准。
先完成 P0，再完成 P1；不能在看到测试集消融结果后更换主指标或任务集合。
